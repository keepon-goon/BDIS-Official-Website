# 匿名信箱

前台入口为 `/feedback`，位于主导航和页脚。后台入口为 `/admin/feedback`，对应“意见收集”。

## 启用

1. 在现有业务数据库中执行 `bdis-website/sql/feedback_migration.sql`。脚本仅创建 `feedback_submission` 和 `feedback_image` 两张新表，可重复执行。
2. 配置 `BDIS_FEEDBACK_STORAGE_ROOT`，指向后台服务可写的持久化目录。默认值为后台工作目录中的 `private-feedback`。附件目录应独立于静态网站目录和 `uploads`，容器部署时需挂载持久化卷。
3. 更新前后端并重启后台服务。保留现有 `/api` 反向代理配置，确认请求体大小允许最多六张各 5MB 的图片。

附件和两张新表需要一同备份。不要为附件目录添加静态资源映射。

## 投递规则

- 不要求姓名、学号、联系方式或账号。
- 文字或图片至少提供一项。文字最多 3000 字，图片最多六张，每张不超过 5MB，仅支持 JPG、PNG。
- 分类为工作室与网站、设备问题、活动建议、其他想法。未选择分类时归入其他想法。
- 后台校验实际图片格式，并在重新编码时去除原始文件名及 EXIF 等元数据，同时修正手机照片方向。
- 提交失败保留当前页面的文字与图片，成功后清空。页面不将意见草稿写入浏览器本地持久化存储。

## 接口

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| POST | `/api/feedback` | 匿名投递，使用 multipart 字段 `category`、`content`、`images` |
| GET | `/api/admin/feedback` | 管理员列表，支持 `page`、`pageSize`、`status`、`category` |
| GET | `/api/admin/feedback/{id}` | 管理员详情 |
| PUT | `/api/admin/feedback/{id}/status` | 更新状态，JSON 字段 `status` |
| GET | `/api/admin/feedback/{id}/images/{imageId}` | 管理员读取附件 |

管理员接口沿用现有 Bearer Token 验证。处理状态为 `UNREAD`、`PROCESSING`、`RESOLVED`。附件响应和查询响应使用 `Cache-Control: no-store`。前台没有公开列表或公开附件接口。

本模块不保存投递者 IP、用户身份或原始文件名。服务器和反向代理的通用访问日志仍由原有运维配置管理，不能将该功能描述为无法追踪的通信服务。

## 验证

在 `bdis-website` 目录执行 `mvnw.cmd -Dtest=FeedbackTest test`。测试使用独立 H2 数据库和临时附件目录，覆盖文字与图片投递、图片校验、失败清理、后台鉴权、附件访问、筛选和处理状态更新。

在 `bdis-web` 目录执行 `npm run build`。实验室公开栏的二维码可直接指向正式网站的 `/feedback` 页面。

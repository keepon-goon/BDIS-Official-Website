# BDIS 项目接口文档：依据当前源码

初次核对日期：2026-10-14，基准提交 `acc2cb503d74bf511c449e353662dfc27d1f5caf`。简历功能更新：2026-10-22，分支 `codex/resume-preview`。源码仓库：BDIS-Official-Website。

本文依据工作区的 Controller、Service、实体、Mapper、拦截器和配置整理。当前共覆盖 **81 个 Controller 接口：20 个访客业务接口、1 个公开文件读取接口、60 个管理功能接口（其中登录无需令牌）**；另记录 `/uploads/**` 静态资源映射。原简历提交接口已改为上传预览，并新增其他 13 个简历接口。

**验证边界：原有非简历模块沿用静态核对结论；新增简历模块已完成 36 项后端测试、浏览器操作、真实本地 MySQL 保存及重启、Ubuntu 容器转换和并发验证。真实 SMTP 投递按用户要求跳过，未部署生产服务器。** 下文 JSON 是结构示例，测试使用虚构资料；其他业务表与生产环境不能据此认定已验收。

## 1. 阅读顺序与联调约定

移动端开发先阅读第 2～5 节；第 6～7 节是现有管理后台接口参考，第一版移动端不必实现后台。

| 项目 | 当前源码行为 |
| --- | --- |
| 后端框架 | Spring Boot 3.2.5，Java 17，MyBatis-Plus 3.5.5 |
| 后端默认地址 | `http://localhost:8081`，来自 `bdis-website/src/main/resources/application.yml` |
| 业务接口前缀 | `/api`；没有配置额外的 servlet context-path |
| 原前端开发代理 | `bdis-web/vite.config.js` 将 `/api`、`/uploads` 转发到 `http://localhost:8081` |
| JSON 字段 | 以实体的 Java 驼峰字段为准，如 `coverThumbUrl`、`sortOrder`，不要发送数据库下划线字段 |
| JSON 请求 | 带请求体的管理接口使用 `Content-Type: application/json` |
| 文件请求 | 使用 `FormData`；浏览器负责生成 multipart boundary，不手工写死 Content-Type |
| 身份认证 | 访客业务无需登录；`/api/admin/**` 除登录外需令牌 |
| 上传限制 | 单文件 10MB、整个 multipart 请求 12MB；简历照片另外限制 5×1024² 字节，手工 Word 限 10×1024² 字节 |
| 跨域 | `WebConfig` 允许任意 origin pattern，支持 GET/POST/PUT/DELETE/OPTIONS；移动端开发仍建议使用同源代理 |
| 编码 | 请求、文件与文档统一 UTF-8 |

### 1.1 成功、业务失败与 HTTP 错误

正常业务接口返回：

```json
{
  "code": 0,
  "message": "ok",
  "data": null
}
```

`data` 根据接口是对象、数组、分页对象或 `null`。`Result.fail(...)` 的结构是：

```json
{
  "code": 1,
  "message": "具体失败原因",
  "data": null
}
```

必须分别检查 HTTP 状态和 JSON 中的 `code`：

- `Result.fail` 通常仍以 HTTP 200 返回，不能只看 HTTP 200 就提示成功。
- 认证失败由拦截器返回 **HTTP 401**，JSON 仍为 `code: 1`。
- 简历两个 Controller 使用范围限定的 `ResumeExceptionHandler`，校验及业务异常采用对应 HTTP 状态和 Result 包装；其他模块没有新增统一异常契约，未知服务器异常仍不保证是 Result。
- 大部分详情查询即使记录不存在，也会返回 `code: 0, data: null`，移动端应显示“内容不存在或已下架”。
- Java `Long` 未配置全局转字符串；本次简历 VO 的编号明确返回 String。其他模块数字 ID 保持原始值，不做加减；超出 JavaScript 安全整数范围的数字需后端处理。

### 1.2 认证

推荐请求头：

```http
Authorization: Bearer <登录接口返回的 token>
```

`AdminAuthInterceptor` 同时接受不带 Bearer 前缀的原始令牌，但新调用方统一采用上面的写法。OPTIONS 请求直接放行。

JWT 配置默认有效期为 86400000 毫秒，即 24 小时，可由 `BDIS_JWT_EXPIRATION` 覆盖。真实环境值未核验；过期后重新登录。当前代码没有提供刷新令牌、服务端登出或访客注册登录接口。

### 2.1 分页对象

公告、资料、搜索的 `data` 结构一致：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [],
    "total": 0,
    "page": 1,
    "limit": 10
  }
}
```

`total` 是总条数，不是总页数。总页数可由 `Math.ceil(total / limit)` 计算。

新闻、项目、竞赛接口直接返回数组，**没有后端页码分页，也没有 total**。传入未声明的 `page` 不会使它们获得分页功能。

## 3. 访客接口详细行为

### 3.1 轮播图：P01

`GET /api/banner`

仅查询 `active = 1` 的记录，按 `sort_order` 升序。`data` 是数组，元素字段见 4.1。

注意字段是 `sortOrder`，没有 `order`；`active` 是整数 0/1。移动端直接保留服务器顺序，不复制桌面组件中基于 `order` 的排序写法。

### 3.2 新闻：P02、P03

`GET /api/news?limit=5&category=notice`

| 参数 | Java 类型 | 默认 | 行为 |
| --- | --- | --- | --- |
| limit | Integer | 0 | 大于 0 时取第一页的指定条数；0 或负数不限制条数 |
| category | String | 不过滤 | 非 null 且非空串时按完全相等过滤；`all` 没有特殊意义 |

按数据库 `order` 升序排列，不按发布时间倒序。列表主动选择 `id/title/category/summary/publish_date/link/cover_thumb_url/order`，**不查询 content**；默认序列化下 `content` 可能出现为 null，不能把它当作详情正文。

`GET /api/news/{id}` 按主键查详情，返回完整实体。示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 1,
    "title": "结构示例：工作室分享活动",
    "category": "activity",
    "summary": "本文用于说明字段结构。",
    "content": "<p>示例正文</p>",
    "publishDate": "2026-10-14",
    "link": "/info/news/1",
    "coverThumbUrl": "/api/uploads/demo.png",
    "order": 0
  }
}
```

`category` 在实体中是 String，没有服务端枚举校验；桌面端使用的常见值为 `recruit/activity/notice/contest/project_recruit`。这些值是现有展示约定，不能据此认定后端拒绝其他字符串。

### 3.3 公告：P04、P05

`GET /api/announcements?page=1&limit=10&category=notice`

| 参数 | Java 类型 | 默认 | 行为 |
| --- | --- | --- | --- |
| page | Integer | 1 | 服务内缺省为 1 |
| limit | Integer | 10 | 服务内缺省为 10 |
| category | String | 不过滤 | null 或 `all` 不过滤；其他值完全相等匹配，空串也会进入过滤 |

按 `sort_order` 升序返回分页。与新闻不同，公告列表没有裁掉 `content` 字段，但列表页仍建议只展示摘要。

公告实体分类为 `recruit/activity/notice/contest/project_recruit`。枚举值与枚举名一致；未发现自定义 JSON 枚举序列化注解。非法 JSON 分类的错误不保证被包装为 Result。

`GET /api/announcements/{id}` 查询公告详情。公告 ID 和新闻 ID 属于不同表，即使数字相同也不是同一内容。移动端必须使用独立的公告详情路由。

### 3.4 实验室和团队：P06、P07

`GET /api/lab/info` 固定读取主键 `1L`，不存在时返回 `data: null`。

`GET /api/lab/team` 返回所有成员，当前没有分页、筛选和明确排序。字段见 4.3～4.4。

联系邮箱、地点和群号建议读取 LabInfo。现有桌面“加入我们”还存在写死的联系信息，移动端不要据此覆盖接口数据；缺值先找负责人核实。

### 3.5 项目进展：P08、P09

`GET /api/projects/progress?limit=5`

`limit: Integer` 可选；省略、0、负数均不限制，大于 0 才限制条数。按 `sort_order` 升序。

`GET /api/projects/{id}` 的 `id` 是 String。不要使用 `Number(id)`、`parseInt(id)` 或把项目 ID 当作连续序号。

列表和详情都会生成 `recruitRolesArray`、`membersArray`。原始字符串也保留，按英文逗号分割；没有逐元素去空格。列表对全空白字符串会返回空数组，详情对全空白字符串的处理稍有不同，展示时仍可 trim 并过滤空项。

实体没有 `content` 或长篇项目介绍字段。第一版详情使用已有名称、副标题、状态、进度、成员等字段，不虚构后端正文接口。

### 3.6 创新竞赛 / 平台：P10、P11

`GET /api/platform/forum?limit=5`

`limit: Integer` 默认 5，直接用于 SQL LIMIT，**0 会得到空列表，不代表取全部**。没有页码、分类、关键词参数。负数没有主动校验，不应发送。

按 `sort_order` 升序；列表和详情均生成 `recruitRolesArray`。

`GET /api/platform/forum/{id}` 的 `id` 是 String。虽然后端命名为 forum，现有桌面将其用于创新竞赛/招募展示；源码中没有访客发帖、评论或点赞接口，不应设计成可交互论坛。

### 3.7 学习资料：P12

`GET /api/resources?page=1&limit=12&category=backend&keyword=Spring`

| 参数 | Java 类型 | 默认 | 行为 |
| --- | --- | --- | --- |
| page | Integer | 1 | 分页 |
| limit | Integer | 12 | 每页条数 |
| category | String | 不过滤 | 非空白字符串完全相等匹配；不把 `all` 当特殊值 |
| keyword | String | 不过滤 | 非空白时模糊匹配 title 或 description；没有 trim 后重新赋值 |

按 `sort_order`、`id` 依次升序。没有公开的 `GET /api/resources/{id}` 接口，资料通过 `link` 打开。

当前调用实体是 **EducationResource**，字段见 4.7。另有 `ResourceItem` 和 `CategoryEnum` 类，但它们没有被该 Controller/Service 用作当前响应和请求校验；不能把 ResourceItem 的 `updatedAt` 写成接口保证字段。

**组合筛选限制：** Service 的条件写法是 `category 条件 + title like + or description like`，没有把两个 like 用括号分组。按该条件构造推断，同时传 category 和 keyword 时，description 命中的其他分类也可能返回；这是源码推断，尚未执行 SQL 验证。前端不要用隐藏结果的办法掩盖问题，应记录 Issue 并交给后端负责人确认。

### 3.8 全站搜索：P13

`GET /api/search?q=Spring&page=1&limit=10`

| 参数 | Java 类型 | 默认 | 必填与校验 |
| --- | --- | --- | --- |
| q | String | 无 | 必填；trim 后为空返回 `code: 1`；完全缺参可能是 Spring HTTP 400 |
| page | Integer | 1 | 未校验正数，前端只发送正整数 |
| limit | Integer | 10 | 未校验正数和上限，前端只发送合理正整数 |

搜索范围仅为新闻 title/summary、公告 title/summary、资料 title/description。**不搜索项目、竞赛、成员，也不搜索新闻正文。**

实现先获取匹配记录，再按“新闻 → 公告 → 资料”拼接，最后在内存切页。新闻内部和公告内部各按 `publish_date` 降序，资料部分没有明确排序，整体不是统一时间排序。

`SearchResult` 是 Controller 组装的 Map：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| type | String | `news`、`announcement`、`resource` |
| id | Long 对应的 JSON 数值 | 来源记录 ID |
| title | String | 标题 |
| summary | String | 新闻/公告摘要或资料 description |
| date | String | 新闻/公告 publishDate；资料为空字符串 |
| link | String | 新闻为桌面路径，公告也被拼成新闻路径；资料为原 link |

移动端按 `type + id` 决定站内跳转，不直接使用后端 link：

| type | 建议移动端行为 |
| --- | --- |
| news | 前往 `/news/{id}`，请求 P03 |
| announcement | 前往 `/announcements/{id}`，请求 P05 |
| resource | 通过校验后的 link 打开资源 |

“资源”没有公开详情接口。搜索返回空数组属于正常空结果；不能显示成网络错误。

### 3.9 简历生成、照片、上传及确认：P14～P20

在线流程：填表 → P16 → 凭证读取 P17/P18 → 可选 P19 换照 → 查看新 PDF → P20 确认。手工流程：P15 下载空白 Word，或 P18 下载当前 Word → 本地编辑贴照 → P14 上传 → P17 预览 → P20 确认。**P14 已不再直接入库或发信；旧客户端必须补上确认步骤。**

P16 使用 JSON，所有正文为纯文本，不接收 HTML 或图片网址：

| 字段 | 类型 | 必填 | 限制 |
| --- | --- | --- | --- |
| name | String | 是 | 最多30字，规范化首尾空白 |
| gender / ethnicity | String | 否 | 分别最多10/30字 |
| college | String | 是 | 最多80字 |
| studentNo | String | 是 | 最多40字，保留前导零 |
| birthMonth | String | 否 | 空串或 YYYY-MM，月份01～12 |
| major | String | 是 | 最多80字 |
| phone | String | 是 | 最多30字，字符串保存 |
| specialties / gpa | String | 否 | 分别最多120/20字 |
| hasCompetitionExperience | Boolean | 是 | 明确 true 或 false |
| intro | String | 是 | 最多800字，可换行 |
| awards / showcase | String | 否 | 各最多500字，风采仅文字和网址文字 |

P14 使用 multipart，必填 `name`、`studentNo`、`phone`，长度同上，必填附件字段名 `resume`。只接受有效 `.docx`，最大10MB；检查压缩内容、宏和外部资源，不接受旧 `.doc`。保留上传原件字节，转换后必须一到两页。从旧预览进入时可附原凭证继承学年；旧凭证过期或不存在不阻止重新上传。索引文字只用于管理和命名，不改写手工文件正文。

P16/P14/P19 成功的 `data` 示例：

```json
{
  "previewToken": "服务器生成的随机凭证",
  "expiresAt": "2026-10-22T13:00:00Z",
  "templateVersion": "two-page-v1",
  "sourceType": "FORM",
  "hasPhoto": false,
  "wordFilename": "测试同学-00001234-2026学年-2027学年大数据智能工作室招新报名表.docx",
  "pdfFilename": "测试同学-00001234-2026学年-2027学年大数据智能工作室招新报名表.pdf"
}
```

`templateVersion` 以实际返回值为准；`sourceType` 是 FORM 或 UPLOAD，手工上传的 `hasPhoto` 为 null，系统不识别原件内有没有照片。临时预览有效期30分钟，不产生正式报名。凭证放请求头 `X-Resume-Preview-Token`，不放 URL；本项目前端只放会话内存，刷新后需重新生成。

P19 使用 multipart `photo` 加凭证，仅 FORM 来源可用。真实 JPEG/PNG，≤5×1024²字节，建议600×900像素、宽高比2:3，相对比例误差≤15%，最多1200万像素；后端处理 JPEG 方向后判断比例。照片等比缩放居中留白，不变形裁切。成功返回新凭证，旧版返回410；失败保留旧有效预览。UPLOAD 来源请本地改 Word 后重传。

所有生成/上传必须实际转换成可读的一到两页 PDF；超过两页返回422。界面保留输入并提供模板和手工上传入口。转换最多1个执行、2个等待，第四个返回429；转换30秒、整次任务120秒上限。

P17/P18 成功返回文件二进制。PDF 为 `application/pdf`，Word 为 DOCX MIME；均 `Cache-Control: no-store`。规范文件名使用 UTF-8 百分号编码的 `X-Resume-Filename`，响应头允许跨域读取；Word 另有 Content-Disposition attachment，PDF不设置此头。前端必须检查 HTTP状态、空文件及 JSON 错误，不能把错误体当 PDF。PDF.js 完成当前全部页绘制后才启用确认。

P20 仅提交当前凭证，不接收姓名、路径或正文。正式保存同版本 Word/PDF 和服务端快照；同凭证重复确认返回原记录，不重复保存或自动发送。成功 `data` 示例：

```json
{
  "submissionId": "3",
  "savedAt": "2026-10-22T21:00:00+08:00",
  "mailStatus": 0,
  "message": "报名已保存，等待管理员发送"
}
```

标题按 Asia/Shanghai 系统日期、9月1日切换，2026年10月和2027年3月均为2026-2027学年；换照、确认、下载沿用原快照学年。文件名为“姓名-学号-2026学年-2027学年大数据智能工作室招新报名表”。空白模板没有姓名学号，使用当年学年和“空白模板”后缀。

## 5. 移动端必须遵守的差异

| 容易误用的地方 | 正确处理 |
| --- | --- |
| 全部列表都写成 result.data.list | 新闻/项目/竞赛/团队/轮播是 result.data；公告/资料/搜索才是 result.data.list |
| 所有列表传 page 都能分页 | 只有公告、资料、搜索具有该分页契约 |
| “全部分类”统一传 all | 新闻、资料省略 category；只有公告专门处理 all |
| 竞赛 limit=0 取全部 | 会得到空列表，使用明确的正整数限制 |
| 公告搜索结果直接使用 link | 按 type 跳转公告详情，不能访问新闻详情接口 |
| 根据本页条数计算 total | 使用服务器 total；无 total 的接口不伪造总条数 |
| 详情 data=null 继续读 title | 先判断空值，显示不存在状态 |
| 直接把 String 项目 ID 转数字 | 全程保留字符串 |
| 复制桌面图片归一化工具 | 先确认资源来源；原工具会改写 /uploads 路径，不适合所有子目录 |
| npm run dev:mock 一定启用 mock | 当前两个 .env 文件都是 VITE_USE_MOCK=false；启动条件还依赖该环境变量，脚本名称不是证据 |
| 成功报名等于邮件成功 | 确认成功表示正式保存，结合mailStatus及message区分邮件结果；SMTP接受也不保证到达收件箱 |
| 现有初始化 SQL 能恢复完整后端 | 简历新增migration/upgrade脚本，加上init_admin.sql仍不包含全部旧业务表和演示数据 |

原业务的分页参数和 limit 没有完整后端校验，移动端统一发送正整数。简历后台单独校验 page≥1、1≤pageSize≤50；前端限制不能替代后端校验。

### 6.3 整体重排的特别规则

`PUT .../reorder` 的请求体必须是整个资源集合的 ID 字符串数组：

```json
["3", "1", "2"]
```

它不是 `{"orderedIds": [...]}`，也不是对象数组。包括 Long 主键的资源，也按照 String[] 契约传字符串。

`AdminSortService` 检查数组非 null、数量相等、没有重复、ID 集合完全一致，并在事务中按数组下标保存 0、1、2……。**必须包含全量记录，不能只提交筛选后的分类或当前可见子集。**

集合变化等校验不通过返回 `code: 1`，消息“排序列表已变化，请刷新后重试”。事务保存失败会抛异常，不保证是 Result 失败包装。

后端变化时，在同一个后端 PR 中说明影响的路径、参数、字段、成功和失败行为，并同步更新本文。记录后端提交号和真实联调日期，不能仅凭旧截图宣称当前版本已通过。

建议用一条只读请求开始联调：

```powershell
Invoke-RestMethod -Method Get -Uri 'http://localhost:8081/api/news?limit=1'
```

PowerShell 的 Invoke-RestMethod 会把 JSON 转成对象，先检查 code，再检查 data。收到空数组只说明当前没有匹配记录；如果请求失败，应按“后端端口 → 代理 → HTTP 状态 → JSON code → 字段结构”顺序定位。真实数据核验由负责人提供测试记录，本文没有执行该命令。

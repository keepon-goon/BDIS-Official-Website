# 简历归档与邮件日志升级说明

更新日期：2026-11-10。本轮功能已随 `20261110-resume-feedback-cd34f8d0` 在生产完成迁移及前后端切换，详见《部署交接.md》第 12 节；浏览器业务操作及新版真实邮件日志仍待验收。此前 `20261109-api-fixes-75f8ee8a` 是另一份已发布的接口修复包，不能将其当成本轮归档与邮件日志版本。

## 1. 后台行为

简历管理列表在“发送/补发”后增加“归档”按钮。已归档记录对应按钮变为“恢复归档”，恢复后重新出现在未归档列表。

归档状态筛选提供“未归档、已归档、全部”，默认“未归档”，切换筛选回到第一页。归档或恢复后刷新当前条件；当前页超出有效页数时，自动回到有效页。

归档只修改 `resume_submission.archived`。姓名、学号、邮件状态、Word/PDF 文件和已有发送日志均保留。归档记录仍可通过“已归档”或“全部”筛选查询、预览、下载和按原规则补发。

详情弹窗底部显示独立邮件发送记录，按开始时间、日志 ID 倒序分页，每页 10 条。展开一条记录，可查看结束时间、异常类型、SMTP 返回码和脱敏后的具体原因。

## 2. 邮件记录与结果语义

每次自动发送或管理员手动发送先登记一条日志，再调用 SMTP。日志记录简历 ID、触发方式、目标邮箱、开始时间、结束时间、耗时和结果。补发会新增记录，原失败记录继续保留。

| 日志状态 | 含义 |
| --- | --- |
| `SENDING` | 本次发送已登记，处理中 |
| `ACCEPTED` | 发送调用正常返回，邮件服务器已接受 |
| `FAILED` | 发送调用抛出异常，具体原因见日志 |
| `UNKNOWN` | 进程重启前未完成结果登记，需要核对收件箱 |

SMTP 受理不等于收件箱投递或已读回执，系统不据此生成实际收件确认。历史异常已经被旧版本丢弃的，不能补回；新版上线前的简历可能只有原来的最新邮件结果，没有独立日志。

日志登记和发送占用标记在同一个数据库事务内完成；SMTP 调用在事务提交后执行。若无法登记日志，停止本次发送并提示“本次未发送”，防止邮件已经发出却完全没有尝试记录。若发送完成后结果登记失败，保留待核实状态，在服务器日志记录实际调用结果；服务重启将未完成记录标记为 `UNKNOWN`，不会自动重复投递。

异常诊断会检查 Spring 邮件异常、嵌套的 Jakarta Mail 异常及 Angus SMTP 返回码。无可用返回码时保持为空，不猜测具体原因。服务器日志包括简历 ID、日志 ID、触发方式、结果和耗时。异常摘要会隐藏已配置授权码及其 Base64 形式、认证字段和邮箱，并清理控制字符；不启用 SMTP 会话全文调试。

## 3. 接口

以下接口均位于管理员鉴权范围，响应禁止缓存。

| 方法 | 路径 | 请求及结果 |
| --- | --- | --- |
| GET | `/api/admin/resumes` | 新增 `archiveStatus=UNARCHIVED/ARCHIVED/ALL`，默认 `UNARCHIVED`；原姓名、学号、邮件状态和分页参数继续生效 |
| PUT | `/api/admin/resumes/{id}/archive` | JSON `{"archived":true}` 归档，`{"archived":false}` 恢复；重复设置同一状态仍成功；不触发邮件 |
| GET | `/api/admin/resumes/{id}/mail-logs` | `page` 默认 1、范围 1～100000；`pageSize` 默认 10、范围 1～50；返回 `{list,total,page,pageSize}` |

列表和详情中的 `ResumeAdminVO` 新增布尔字段 `archived`。邮件日志包含字符串 `id`、`triggerType`、`recipient`、`status`、`startedAt`、`finishedAt`、`durationMs`、`errorType`、`smtpCode`、`errorMessage`。

参数错误返回 400；未登录或令牌无效返回 401；简历不存在返回 404。原发送并发保护继续生效，同一简历正在发送时再次发送返回 409，且不会多建一条实际发送日志。

## 4. 数据库升级与部署顺序

已有生产库使用单独的增量文件：`bdis-website/sql/resume_archive_mail_log_migration.sql`。新增 `archived TINYINT NOT NULL DEFAULT 0` 和相应查询索引，并创建 InnoDB、UTF-8 的 `resume_mail_log` 表。已有简历默认未归档。

部署前先备份，并在实际业务库执行只读核对：

```sql
SHOW COLUMNS FROM resume_submission LIKE 'archived';
SHOW INDEX FROM resume_submission WHERE Key_name = 'idx_resume_archive_created';
SHOW TABLES LIKE 'resume_mail_log';
SHOW TABLE STATUS WHERE Name = 'resume_submission';
```

归档列、归档索引和日志表均不存在，且简历表使用 InnoDB 时，执行增量文件一次。若任何一项已存在，先逐项核对，不能盲目重跑整份文件；该文件中的 `ALTER TABLE` 和 `CREATE INDEX` 不支持重复执行。若上次只执行了一部分，明确剩余语句后再继续。

正确顺序为：备份与结构核对 → 应用增量 SQL → 核对新列、索引和日志表 → 切换新版后端并检查就绪 → 切换前端 → 验收归档、恢复和邮件历史。

新环境的建表文件 `bdis_init.sql` 和 `resume_submission_migration.sql` 已同步本轮结构。已有生产库不能用初始化文件替代增量迁移。服务启动不会自动执行仓库 `sql/` 下的迁移。

本轮表结构是增量兼容变更。程序回退时保留新增字段和日志表；删除日志表或恢复旧数据库备份会丢失新增记录，不作为自动回退操作。部署继续沿用《部署交接.md》中的正式环境文件、私有附件目录和 systemd 服务。

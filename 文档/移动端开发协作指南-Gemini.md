（基于 Vue 3 与现有后端接口的 1～2 周攻坚冲刺）

	先把心放回肚子里。这篇指南不扯任何虚头巴脑的高调，也不会扔一堆前端黑话把你们绕晕。我想用最平实、最透彻的大白话，帮你们把这件事情看清楚，稳稳接住你们手头的这个冲刺任务。
	一两个星期的周期确实很紧凑，但正因为时间紧，我们更要把每一块好钢都用在刀刃上，绝不走弯路，绝不搞花拳绣腿。“这世上绝大多数组织都是草台班子”，前端工程同样没有什么高不可攀的玄机。你们既然已经理解了后端 Controller 怎么处理请求、JSON 数据在网络上怎么跑，这就已经是最大的底牌了。所谓的移动端前端，本质无非就是：把后端吐出来的 JSON 数据，体面、规整地排在手机屏幕上；在用户按按钮时，顺畅地发一个 HTTP 请求出去。仅此而已。
	这一两周千万别想着成为什么前端架构大师，也不要脱离实际去把整个 Vue 全家桶从头啃一遍。两个人分工明确、步步为营：前两三天立住规矩把架子搭好，中间几天集中火力把真实接口一个一个打穿，最后两三天搞定真机实测和打包。只要每一个合入代码库的功能都有真实数据、都能处理报错、自己都讲得清原理，一两周时间完全足够你们交出一个经得起考验的扎实作品。
	另外谈谈 AI 工具。在这一两周的快速突击里，善用 AI（如 Claude Code、Cursor、Codex 等）确实能帮你们省去大量查语法的死功夫，但最大的陷阱在于“自我麻痹”：很多人让 AI 噼里啪啦生成了几百行代码，看着挺好看就完事了，结果控制台一堆 warning，接口根本没通全是写死的假数据，手机上一跑排版直接撕裂，自己连代码里的变量代表什么都答不上来——这不叫敏捷开发，这叫给 AI 当人肉搬运工。
	你们要学会跟 AI 达成健康的共生状态：用它来做语法解惑、写局部代码片段、排查疑难报错，但绝对不能让它代管工程。我的底线要求很明确：你可以写得比 AI 慢，但每一行进代码库的代码，必须是你自己理解、亲手跑通并验证过的。
	放下杂念，理清脉络，我们直接开始拆解这一两周的战斗路径。

一、项目背景与 1～2 周冲刺目标
	大数据智能工作室（BDIS）官网移动端，核心目标是为手机端访客打造一个轻量、清晰、快速的浏览窗口。我们不重新造轮子，而是直接复用工作室现有的 Spring Boot 后端接口；由两名前端零基础但具备后端常识的同学（A 同学与 B 同学），在负责人的协助下，通过一个独立的 GitHub 公开仓库，用标准工业流程在 1～2 周（约 10～14 天）内协同完成。
	必须再次明确定位：原桌面端重点是后台管理与宽屏展示，用了 Element Plus 这种庞然大物；而移动端追求的是在有限的手机屏幕宽度里把内容交代清楚。第一版的核心是内容浏览，包括首页、动态资讯、项目展示、竞赛招募、资料检索、关于与加入、全局搜索，以及一个预留的成长路线页。
	我们不做复杂的访客登录，也坚决不搞自欺欺人的“假成功按钮”——后端没有提供在线投递简历和即时报名的接口，我们就老老实实展示投递邮箱和下载链接，绝不搞一个点了就弹窗“报名成功”的虚假交互。
	这 1～2 周的紧凑作战划分为六个冲刺阶段：
	1. 冲刺阶段一（第 1～2 天）：协作环境准备、仓库规则与最小工程基建（立好工程规矩）。
	2. 冲刺阶段二（第 3～4 天）：单列移动端骨架、底部导航与全路由注册（铺好基础路线）。
	3. 冲刺阶段三（第 5～6 天）：打通第一个真实 HTTP 网络闭环——新闻与公告（穿透核心数据链路）。
	4. 冲刺阶段四（第 7～9 天）：业务主干推进——首页聚合、项目展示与竞赛招募（攻克复杂数据展示）。
	5. 冲刺阶段五（第 10～11 天）：综合信息检索——学习资料分类、关于我们与全局搜索（攻克联动与防抖）。
	6. 冲刺阶段六（第 12～14 天）：架构留白、脱离 AI 的独立手写练习、真机实测与终验交付（完成冲刺验收）。

二、技术选型与减负：用后端思维快速理解前端
	在短周期内，技术选型必须遵循“极简、可控、贴近底层”的原则，绝不引入会拖慢进度的复杂框架：
	- 视图层：Vue 3（采用官方推荐的 `<script setup>` 组合式写法）。
	- 构建工具：Vite。
	- 路由体系：Vue Router（首版使用更易于静态托管与局域网调试的 Hash 模式）。
	- 网络请求：浏览器原生 `fetch` 极简封装。
	- 样式排版：基础 CSS（以移动端最核心的 Flexbox 弹性布局为主）。

	为了在两周内打胜仗，我们坚决剔除一切形式主义负担：
	- 不引入 TypeScript：避免刚入门就陷入繁杂的类型体操。
	- 不引入 Pinia 等全局状态库：当前以单向数据展示为主，组件内的响应式变量完全管够。
	- 坚决不搬运桌面端组件库：移动端的单列排版并不复杂，手写基础样式是建立 CSS 直觉的最快途径。

	后端同学往往觉得前端术语花哨，其实只要对应到你们熟悉的后端概念，瞬间就能想通：
	- HTML：相当于页面的“实体骨骼”，定义哪里是标题、哪里是列表、哪里是输入框。
	- CSS：相当于“格式化输出配置”，决定字体大小、外边距内边距、元素是横排还是竖排。
	- JavaScript：相当于“控制器逻辑”，负责监听用户的点击动作、发起 HTTP 请求、清洗数据。
	- `.vue` 单文件组件：相当于把一个业务界面的视图定义、控制逻辑和样式规则，打包在一个高内聚的文件里。
	- `Vue Router`：相当于前端内部的“路由分发器”（类比 Spring MVC 的 `@RequestMapping`）。用户在浏览器地址栏切换 `/#/news/1`，路由就加载对应的新闻组件。但千万记住：前端路由改变不等于向后端发了请求，组件挂载后依然要自己用代码去发网络请求。
	- `ref`：相当于一个“自带监听器的变量包装器”。你在脚本里修改它的 `.value`，Vue 就会感知到并自动帮你刷新屏幕上绑定的那一小块内容。
	- `v-if / v-else` 与 `v-for`：就是模板里的条件判断与 `for-each` 循环，用来分别控制加载中/失败/空数据的切换，以及遍历渲染列表项。
	- `package.json` 与 `package-lock.json`：完全对应 Maven 的 `pom.xml` 与依赖解析锁定机制；而庞大的 `node_modules/` 目录就相当于本地 Maven 缓存，**绝对不能提交到 Git 仓库里**。
	- Vite 开发代理：就相当于在开发阶段由 Vite 在本地充当一个简易 Nginx，帮你把以 `/api` 开头的请求转发到 Spring Boot 后端，以此绕过浏览器的跨域限制。

三、动手前的规矩与条件准备

1. 开发环境基线
	两人统一使用 Node.js 22 LTS（建议 22.18.0 或以上版本），并在项目 README 中明确注明。代码编辑器统一推荐 VS Code（必装 Vue - Official 插件）或 WebStorm。在终端确认 `node -v` 和 `npm -v` 能够正确打印版本号。在 Windows 环境下，若遇 PowerShell 执行策略报错，使用 `npm.cmd` 运行即可，不要贸然修改全局安全策略。

2. 后端联调条件准备
	联调不是抓瞎碰运气。在正式开工前，实验室负责人必须为两位同学备齐以下基础条件：
	- 提供一个能在局域网稳定连通的后端服务地址（如 `http://localhost:8081` 或指定内网 IP）。
	- 数据库中准备好新闻、公告、项目、竞赛、资料等维度的代表性测试数据；并且每种详情接口，都必须提供一个真实存在的 ID，以及一个确认不存在的 ID（用来验证前端面对 404 时的容错表现）。
	- 明确图片资源的映射机制（哪些是后端通过 `/uploads` 提供的动态图，哪些属于前端本地静态图）。
	- 严禁在公开代码库中记录真实数据库密码、内部令牌或个人隐私联系方式。

3. 独立公开仓库与协同规矩
	移动端代码放在单独的 GitHub 公开仓库中（建议命名为 `bdis-mobile`），本地存放在如 `D:/java/bdis-mobile` 的独立目录。**严禁在原后端项目仓库的子目录下直接套娃新建前端仓库！**
	由 A 同学在 GitHub 新建仓库并邀请 B 同学加入协作，两人使用同仓分支模式。提交信息必须清楚说明本次做了什么（如 `feat: 增加移动端新闻详情页`、`fix: 修复分类切换未重置页码问题`），坚决杜绝“修改”、“update”等糊弄人的提交日志。

4. 推荐备查资料
	- Vue 3 官方文档：快速起步、响应式基础与模板语法。
	- Vite 官方文档：开发服务器与 proxy 代理配置。
	- MDN Web 文档：Flex 弹性布局与 Fetch API 指南。
	- B 站精选实用教程（查漏补缺用，不要沉迷刷视频）：
	  * 《Vue3 + Vite 快速上手 零基础保姆级前端教程》
	  * 《Git 与 GitHub 团队规范化协作实战》
	  * 《HTTP 协议与浏览器网络请求链路从入门到吃透》

四、冲刺阶段一（第 1～2 天）：协作准备、仓库规则与最小工程基建

阶段目标
	头两天必须把团队协作的章法完全立起来。A 同学负责在 GitHub 创建公开仓库并配置主分支保护；随后拉取本地分支，使用官方工具创建纯净的 Vue 3 工程（配置为 Hash 路由，不勾选 TS、Pinia 及各类复杂测试工具），添加严密的 `.gitignore`，并配置好最小的 GitHub Actions 持续集成脚本（`build.yml`）。B 同学负责在自己电脑拉取分支，验证本地安装与编译，并对 A 的初始化 PR 进行线上 Review 与合入。

完成要求
	1. 仓库公开，A、B 两人均有推送与评审权限。
	2. `main` 分支开启保护规则：禁止直接 push，必须通过 PR 合并；必须至少有 1 位其他成员 Approve；必须通过 GitHub Actions 构建检查；只允许 Squash and merge。
	3. `.gitignore` 严密生效，绝不允许 `node_modules/`、`dist/` 或个人配置被推上远端。
	4. 建立 `.github/workflows/build.yml`，在每次 PR 和 push 时自动跑通 Node 22 环境下的 `npm ci` 与 `npm run build`。

实践任务
	1. A 同学在本地新分支执行 `npm create vue@latest .` 初始化项目，只选 Vue Router，其余选否；调整路由为 Hash 模式并清理冗余样例代码。
	2. 在 `.github/workflows/build.yml` 写入最小构建检查：
```yaml
name: 移动端构建检查

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  build:
    name: build
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
      - run: npm ci
      - run: npm run build
```
	3. A 同学向 `main` 发起初始化 PR。
	4. B 同学在本地检出该分支，运行 `npm ci`、`npm run dev` 和 `npm run build`，确认本地能顺利跑起来且云端 CI 变绿后，点击 Approve 并合并。

交付证据
	仓库地址、初始化 PR 链接、主分支保护设置截图、CI 首次成功运行日志。

做完这些后
	你们已经把工程的地基牢牢打住了！
	很多新手在赶时间时喜欢跳过这一步直接在本地乱写，结果越往后代码越乱，最后合代码时天崩地裂。现在，主分支受到了严格保护，云端流水线为每一次提交站岗。你们迈出了正规工程协作最坚实的一步。接下来，我们去给手机端勾勒骨架。

五、冲刺阶段二（第 3～4 天）：单列移动端骨架、底部导航与全路由注册

阶段目标
	这两天由 B 同学主导，搭建专门适配手机小屏幕的流式单列骨架。实现上下固定、中间内容平滑滚动的布局体系（`MobileLayout.vue`），制作贴合手机下边缘安全区的底部导航栏（`BottomNav.vue`），统一封装多状态展示组件（`RequestState.vue`），并在路由中把第一期规划的 14 个路由节点全部注册到位。

完成要求
	1. 页面在 320px、375px、390px、430px 等不同手机宽度下均能自适应展现，绝对不能出现横向滚动条，也不能使用简单的 `overflow-x: hidden` 去强行掩耳盗铃。
	2. 底部导航包含“首页、动态、项目、资料、更多”五个核心入口，高亮与路由状态实时联动，点击切换顺畅。
	3. 完整注册 14 个核心业务路由，所有非法或未匹配路径全部优雅重定向至 404 兜底页，并带有“返回首页”快捷按钮。

实践任务
	1. B 同学开辟新分支，编写 `MobileLayout.vue` 与 `BottomNav.vue`。
	2. 在 `src/router/index.js` 中完整登记全站路由清单：
		- `/`（首页）
		- `/updates`（动态：新闻与公告聚合）
		- `/news/:id`（新闻详情）
		- `/announcements/:id`（公告详情）
		- `/projects`（项目列表）
		- `/projects/:id`（项目详情）
		- `/competitions`（竞赛招募列表）
		- `/competitions/:id`（竞赛招募详情）
		- `/resources`（学习资料）
		- `/about`（关于我们）
		- `/join`（加入说明）
		- `/search`（全局搜索）
		- `/growth`（成长路线预留页）
		- `/:pathMatch(.*)*`（404 兜底）
	3. A 同学在本地拉取分支，在浏览器开发者工具中切换多种手机尺寸，重点检查底部导航是否遮挡正文内容，确认无误后通过 PR。

交付证据
	骨架 PR 链接、多尺寸手机模拟效果截图、导航路由切换演示录屏、404 返回流转测试记录。

做完这些后
	移动端的骨骼经络已经全部通顺了！
	在手机屏幕里，各个页面的入口已经各就各位，不论用户怎么点，都不会迷路，也不会撞进死胡同。虽然页面里暂时还只有骨架，但这个架子是坚固且合规的。接下来，我们要迎来全剧最关键的一步——打通真实网络数据！

六、冲刺阶段三（第 5～6 天）：打通第一个真实 HTTP 网络闭环——新闻与公告

阶段目标
	这是整个项目从“空壳静态玩具”蜕变为“真实可用系统”的生死线。我们要直面真实的网络通信，搞清楚 Vite 开发代理（`server.proxy`）是怎么把浏览器发出的请求稳稳转给后端的。用原生 `fetch` 封装底层数据请求方法，理清网络报错与业务报错的区别。A 同学攻克新闻列表与详情，B 同学攻克公告列表（含分类与分页）与详情，共同落实“加载中、请求失败、数据为空、正常展示”四种状态闭环。

完成要求
	1. 在 `vite.config.js` 中配通 `/api` 与 `/uploads` 的代理，彻底扫除跨域阻碍。
	2. 编写通用的 `getData(path)` 函数，严格区分 HTTP 状态码异常与后端业务码 `code !== 0` 的异常。
	3. 页面决不允许在接口报错或断网时白屏装死，必须呈现直观的错误提示并配有“重新加载”按钮；当列表为空时，友好展示“暂无数据”说明。
	4. 详情页能够妥善应对路由参数变化，连续点开不同新闻时，页面能够及时拉取新 ID 的内容。

核心代码参考（务必亲手敲入并搞懂每一句，严禁盲目复制）
	`src/api/http.js`：
```javascript
export async function getData(path) {
  const response = await fetch(path)
  if (!response.ok) {
    throw new Error('网络请求异常：HTTP ' + response.status)
  }
  const result = await response.json()
  if (result.code !== 0) {
    throw new Error(result.message || '业务处理失败')
  }
  return result.data
}
```
	`src/api/news.js`：
```javascript
import { getData } from './http.js'

export function getNewsList() {
  return getData('/api/news?limit=10')
}

export function getNewsDetail(id) {
  return getData(`/api/news/${id}`)
}
```
	新闻列表组件核心逻辑：
```vue
<script setup>
import { ref, onMounted } from 'vue'
import { getNewsList } from '../api/news.js'

const items = ref([])
const loading = ref(false)
const error = ref('')

async function load() {
  loading.value = true
  error.value = ''
  try {
    items.value = await getNewsList()
  } catch (e) {
    error.value = e.message || '数据加载失败，请重试'
  } finally {
    loading.value = false
  }
}

onMounted(load)
</script>

<template>
  <div class="news-container">
    <h2>最新动态</h2>
    <div v-if="loading" class="tip-box">正在加载中...</div>
    <div v-else-if="error" class="tip-box error-box">
      <p>{{ error }}</p>
      <button type="button" @click="load">点击重试</button>
    </div>
    <div v-else-if="items.length === 0" class="tip-box">暂无相关动态</div>
    <ul v-else class="list-box">
      <li v-for="item in items" :key="item.id">
        <router-link :to="`/news/${item.id}`">
          <h3>{{ item.title }}</h3>
          <span>{{ item.publishDate || item.createTime }}</span>
        </router-link>
      </li>
    </ul>
  </div>
</template>
```

十二、附录：给后端同学的前端实战避坑手册

| 常见现象 / 报错 | 顺着这里排查（第一反应） | 本质原因与技术点 | 解决招数 |
| :--- | :--- | :--- | :--- |
| **HTTP 状态码是 200，但页面却提示处理失败** | 看 Network 里返回的 JSON，找 `code` 和 `message` | HTTP 协议通信成功，不等于后端业务处理成功 | 后端返回了业务错误（如 `code: -1`），前端要解析并展示 `result.message` |
| **报错：Cannot read properties of undefined (reading 'map' 或 'length')** | 在 Network 中确认返回的 `data` 到底是个列表、带分页的对象还是 `null` | 数据结构没对齐，缺乏空值防御 | 变量初始化给 `ref([])`，在模板渲染前使用可选链或 `v-if` 做非空拦截 |
| **新闻列表传了 page 但页面死活不翻页** | 翻出接口文档核对新闻接口支持的 Query 参数 | 后端接口压根没做这个功能 | 新闻接口只支持 `limit`，后端没写分页逻辑就不要强行传 `page` |
| **点开公告详情，里面展示的居然是一篇新闻的内容** | 检查跳转的路由路径，以及组件内部调用的 API 函数名 | 数据隔离与命名疏忽 | 新闻和公告的数字 ID 极易撞车，检查是不是在公告页面错调了 `getNewsDetail` |
| **分类选“全部”时后端查不到任何数据** | 看看发出的网络请求是不是带了 `category=all` | 参数清洗不到位 | 选“全部”时传空字符串 `""` 或不传该参数，严禁把单词 `"all"` 当成类别发过去 |
| **电脑浏览器跑得欢，手机连上却一直在转圈或者报错** | 检查代码里的请求 URL 是否硬编码了 `localhost`，检查电脑防火墙 | 局域网网络拓扑常识 | 手机里的 `localhost` 指的是手机自己！必须在电脑启动 Vite 代理并访问电脑内网 IP |
| **首页头图或成员头像直接报 404** | 检查图片路径前缀是 `/uploads`、`/api/uploads` 还是本地路径 | 静态资源托管归属 | 后端上传图需配 Vite 代理转发到 `/uploads`，前端自备图标请放入 `public/` 目录 |
| **点进项目详情后 ID 变成了另一串数字或者直接 404** | 检查代码里是不是对 ID 执行了 `Number(id)` 或 `parseInt` | 大数值精度截断 | 雪花 ID 或长字符串主键在 JS 里转数字会丢精度，必须全程当作纯字符串处理 |
| **搜索框快速打字，最后屏幕上停在旧的搜索结果上** | 检查连续输入时是否有防抖，慢请求后返回把新请求冲掉了 | 异步网络请求竞态（Race Condition） | 加上请求防抖（Debounce），或者在发起新请求时记录序列号/取消先前请求 |
| **本地 `npm run dev` 正常，打包后白屏或静态资源全 404** | 检查 Vite 的 `base` 配置，以及路由是不是没有配置 Hash 模式 | 生产环境资源相对路径 | 首版严格使用 Hash 模式（`createWebHashHistory`），确保静态资源相对路径正确 |
| **GitHub PR 页面上的绿色 Merge 按钮是灰色的按不下去** | 检查是否有同伴的 Change requested 没撤销、CI 没跑过或代码有冲突 | 主分支保护机制在生效 | 解决冲突、拉最新代码、等待 CI 变绿、让同伴给出有效 Approve 即可解锁 |

	总之，祝各位前程似锦！

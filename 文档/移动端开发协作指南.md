### 写在前面：心智破局与冲刺定调

如果你们刚把 Spring Boot 的增删改查和 Maven 依赖稍微整明白，突然接到通知要在短短一两周内把移动端前端做出来，心里大概率会犯嘀咕：“我们两个纯纯的后端底子，一两个星期写个前端移动端出来，这时间是不是太赶了？”“我连 CSS 居中都还没闹明白，这不得抓瞎？”

先把心放回肚子里。这篇指南不扯任何虚头巴脑的高调，也不会扔一堆前端黑话把你们绕晕。我想用最平实、最透彻的大白话，帮你们把这件事情看清楚，稳稳接住你们手头的这个冲刺任务。

一两个星期的周期确实很紧凑，但正因为时间紧，我们更要把每一块好钢都用在刀刃上，绝不走弯路，绝不搞花拳绣腿。“这世上绝大多数组织都是草台班子”，前端工程同样没有什么高不可攀的玄机。你们既然已经理解了后端 Controller 怎么处理请求、JSON 数据在网络上怎么跑，这就已经是最大的底牌了。所谓的移动端前端，本质无非就是：**把后端吐出来的 JSON 数据，体面、规整地排在手机屏幕上；在用户按按钮时，顺畅地发一个 HTTP 请求出去。仅此而已。**

这一两周千万别想着成为什么前端全栈大师，也不要脱离实际去把整个 Vue 全家桶从头背一遍。两个人分工明确、步步为营：前两三天立住规矩把架子搭好，中间几天集中火力把真实接口一个一个打穿，最后两三天搞定真机实测和打包。只要每一个合入代码库的功能都有真实数据、都能处理报错、自己都讲得清原理，一两周时间完全足够你们交出一个经得起考验的扎实作品。

**关于 AI 工具的底线约定：**
在这一两周的快速突击里，善用 AI（如 Claude Code、Cursor、Codex 等）确实能帮你们省去大量查语法的死功夫，但最大的陷阱在于“自我麻痹”：很多人让 AI 噼里啪啦生成了几百行代码，看着挺好看就完事了，结果控制台一堆 warning，接口根本没通全是写死的假数据，手机上一跑排版直接撕裂，自己连代码里的变量代表什么都答不上来——这不叫敏捷开发，这叫给 AI 当人肉搬运工。
你们要学会跟 AI 达成健康的共生状态：用它来做语法解惑、写局部代码片段、排查疑难报错，但绝对不能让它代管工程。底线要求很明确：**你可以写得比 AI 慢，但每一行进代码库的代码，必须是你自己理解、亲手跑通并验证过的。**

## 1. 最终要做成什么与 1～2 周冲刺节奏

制作一个专门面向手机浏览器的 BDIS 官网，直接复用现有 Spring Boot 接口，在单独的 GitHub **公开仓库**中协同开发。

第一版的核心是内容浏览，包括首页、新闻与公告、项目与竞赛、学习资料、关于我们、加入说明、全局搜索，以及一个可访问的“成长路线”预留页。以清晰的内容浏览为主，不要求访客登录。

管理后台继续使用原桌面端。加入页面展示报名表下载，但必须确认文件来源真实可靠；在线收集简历作为后续单独 Issue，在满足后端前置条件后再接入。**坚决杜绝假功能**：没有评论、点赞、在线组队、报名查询等接口，不设计“点击就弹窗假装成功”的欺骗性按钮。

### 1.1 结项时的个人能力闭环
冲刺完成后，每位同学都要能够：
1. 脱稿讲清一个页面从点击入口、路由跳转、发起网络请求，到把 JSON 渲染在屏幕上的全链路。
2. 熟练看懂并修改 Vue 模板语法、基础 CSS 排版、条件分支与循环渲染；能完全脱离 AI 独立手写并调通一个小改动。
3. 在浏览器 Network 面板中精准区分网络断开、代理失效、HTTP 错误（4xx/5xx）、业务失败（`code !== 0`）与数据为空。
4. 规范、熟练地执行 GitHub flow：Issue 认领、分支派生、规范提交、PR 提交、交叉代码审查、冲突解决与分支合并。
5. 清晰解释自己提交的每一段 AI 辅助代码，并能举出一次自己发现并纠正 AI 幻觉/误导的具体案例。

### 1.2 冲刺时间节奏安排（10～14 天）
| 阶段划分 | 对应时间 | 核心战役目标 | 关键产出 |
| :--- | :--- | :--- | :--- |
| **冲刺一** | 第 1～2 天 | 协作环境准备、仓库规则与最小工程基建 | 公开仓库创建、分支保护开启、最小 Actions CI 跑通 |
| **冲刺二** | 第 3～4 天 | 移动端单列骨架、底部导航与全路由注册 | 320px/390px 布局无横向溢出、14 个路由注册、404 返回 |
| **冲刺三** | 第 5～6 天 | 打通第一个真实网络闭环——新闻与公告 | 原生 fetch 封装、开发代理、四种数据状态、详情路由 |
| **冲刺四** | 第 7～9 天 | 业务主干推进——首页聚合、项目展示与竞赛招募 | 首页多接口容错、项目长字符串 ID 保护、竞赛招募展示 |
| **冲刺五** | 第 10～11 天 | 综合信息检索——学习资料、关于/加入与全局搜索 | 资料筛选重置、真实下载入口、全局搜索防抖与跳转防串 |
| **冲刺六** | 第 12～14 天 | 架构留白、独立手写练习、真机实测与终验交付 | `/growth` 预留、脱离 AI 手写 Diff、局域网真机实测、生产构建 |

## 2. 技术选型与最小知识

### 2.1 统一技术选型
| 技术维度 | 本次选择 | 决策考量与减负原则 |
| :--- | :--- | :--- |
| **页面框架** | Vue 3（Composition API + `<script setup>`） | 官方主流标准，代码清晰高内聚；对照原桌面端易于理解 |
| **工程工具** | Vite（使用官方 `create-vue` 脚手架） | 极速冷启动，秒级热重载，开箱即用 |
| **路由方案** | Vue Router（首版使用 Hash 模式） | 路由独立，无需生产服务器复杂回退配置，便于局域网真机调试 |
| **网络请求** | 浏览器原生 `fetch` 极简封装 | 零额外第三方依赖，直接贴近原生 HTTP 与异步本质 |
| **样式排版** | 原生 CSS + Flexbox 弹性布局 | 单列移动端排版足矣，手写基础样式是建立布局直觉的最短路径 |
| **状态管理** | 组件内 `ref` / `computed`，配合少量 `props` | 当前规模以接口直接呈现为主，坚决不引入复杂的 Pinia 全局状态库 |
| **代码协作** | Git + GitHub Issues + PR + Actions | 现代工业化标准协同，每一次变更均有迹可循、有据可查 |
| **质量检查** | GitHub Actions 自动化构建 + 人工真实核验 | CI 负责拦截语法与打包错误，人工负责检验交互与手机显示 |

**包袱清理**：首版坚决不用 TypeScript、Pinia、Element Plus 桌面组件库、富文本编辑器、复杂动画或微前端。避免把时间浪费在工具环境折腾上。

### 2.2 用后端经验降维理解前端概念
| 前端名词 | 先这样理解（后端对应概念） | 在本项目中的具体作用 |
| :--- | :--- | :--- |
| **HTML** | 页面的“实体骨骼” | 组织内容标题、段落、列表容器、搜索输入框 |
| **CSS** | 页面的“格式化排版规则” | 控制移动端单列流式布局、内外边距、底部导航吸底 |
| **JavaScript** | 页面的“业务逻辑控制器” | 监听用户点击、发起异步网络请求、清洗 JSON 数据 |
| **.vue 单文件组件** | 视图、逻辑与样式高内聚的业务模块 | 承载一个页面（如 `HomeView.vue`）或通用卡片 |
| **Vue Router** | 前端内部的“地址调度分发器”（类比 `@RequestMapping`） | 用户访问 `/#/news/1` 时调度渲染对应的新闻组件 |
| **props** | 方法调用的入参（Method Arguments） | 父组件向子组件单向传递数据（如把单项数据传给卡片） |
| **ref** | 自带监听器的响应式变量封装体 | 修改其 `.value` 时，Vue 会自动刷新屏幕绑定的对应区域 |
| **computed** | 实体的 Getter 派生计算属性 | 根据已有数据自动计算衍生值（如符合条件的结果数量） |
| **v-if / v-else** | 模板里的 `if-else` 分支控制 | 分别切换：加载骨架屏、报错重试、空数据提示、正常列表 |
| **v-for / :key** | 模板里的 `for-each` 循环遍历 | 循环遍历渲染卡片列表，`:key` 绑定数据库主键 ID |
| **v-model** | 视图与变量的双向绑定 | 搜索输入框内的文字与 JS 变量实时同步 |
| **fetch / async await** | 原生 HTTP 客户端（类比 RestTemplate / HttpClient） | 异步向 Spring Boot 发送请求并解析响应正文 |
| **package.json** | 项目依赖与指令声明（完全对标 `pom.xml`） | 管理项目第三方依赖库与构建运行命令 |
| **package-lock.json** | 依赖最终解析版本锁定文件 | 确保团队两人与 CI 机器安装出的库完全一致（**必须入库**） |
| **Vite Proxy** | 开发阶段的简易本地 Nginx 反向代理 | 帮浏览器将 `/api` 请求转发到后端的 `localhost:8081`，解决跨域 |

> [!IMPORTANT]
> **前端路由不等于后端 Controller**：浏览器内部切到 `/#/news/1`，仅仅是 Vue 加载了组件结构；该组件必须在 JS 代码中显式调用 `fetch('/api/news/1')`，才能真正向后端索取数据。

## 3. 开工前的协作条件与环境准备

### 3.1 负责人提供的后端联调支撑
严禁两名前端新手在“无测试服务、无有效数据”的盲盒状态下猜接口。负责人必须在开工前备齐：
1. **测试服务**：提供一个稳定的后端访问地址（如本机 `http://localhost:8081` 或指定内网 IP）。
2. **测试数据种子**：新闻、公告、项目、竞赛、资料各录入具有代表性的数据。
3. **关键测试 ID**：每类详情接口必须提供至少一个真实存在的 ID，以及一个确认不存在的 ID（用于验证 404 容错）。
4. **图片映射规则**：明确 `/uploads` 静态映射规则，确认哪些图片属于后端上传，哪些由前端本地自备。
5. **安全脱敏**：确认联系方式、报名表下载地址可公开，公开代码库中严禁包含任何内部密码、令牌或隐私信息。

### 3.2 独立公开仓库规范
移动端代码必须存放于单独的 GitHub **公开仓库**（推荐命名为 `bdis-mobile`），本地存放在如 `D:/java/bdis-mobile` 的独立目录。**严禁在原后端项目内部嵌套建立第二个 `.git` 仓库！**

操作规约：
1. A 同学在 GitHub 创建该公开仓库，默认分支为 `main`，勾选初始化 README。
2. A 在仓库设置中邀请 B 同学加入协作，B 确认接受邀请并具备推送分支与 Review 权限。
3. 两人均采用“同仓分支协同”模式，所有的功能更新均通过功能分支提交 PR，严禁直接向 `main` 强推代码。
4. 规范配置 `.gitignore`，严禁将依赖与产物推向远端：
```gitignore
node_modules/
dist/
.env
.env.*
!.env.example
*.log
.idea/
.vscode/
uploads/
```

### 3.3 建立主分支保护规则（Branch Protection）
公开仓库免费支持分支保护。在 GitHub 仓库设置中针对 `main` 建立以下刚性规则：
1. 开启 **Require a pull request before merging**。
2. 开启 **Require approvals**，数量设为 **1**（合并前必须经过对方批准）。
3. 开启 **Dismiss stale pull request approvals when new commits are pushed**（代码变更后旧批准失效）。
4. 开启 **Require status checks to pass before merging**，将后续的 `build` 工作流设为必须通过项。
5. 勾选 **Do not allow bypassing the above settings**（规则约束所有人）。
6. 合并策略**仅保留 Squash and merge**，保持 `main` 分支历史紧凑干净。

### 3.4 最小 CI 自动化构建配置
在项目根目录下创建 `.github/workflows/build.yml`：
```yaml
name: 移动端构建检查

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  build:
    name: build
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: npm
      - run: npm ci
      - run: npm run build
```
> [!NOTE]
> 绿色的 build 只能证明工程能够正常编译生成产物，不能证明页面好用、接口连通或手机排版正常。这些必须在 PR 中附加真实验收证据。

## 4. 页面契约、推荐目录与协作规则

### 4.1 第一版 14 个核心业务路由契约
底部主导航设计为五大入口：“首页、动态、项目、资料、更多”。“更多”中容纳关于我们、加入说明、全局搜索与成长路线预留页。

| 内部路由路径 | 页面核心内容 | 对接后端真实接口 | 负责开发 / 评审 |
| :--- | :--- | :--- | :--- |
| `/` | 简介、头图/轮播、微缩动态、快捷入口 | `/api/lab/info`、`/api/banner`、`/api/news?limit=3` | A / B |
| `/updates` | 动态总览：新闻与公告聚合切换 | `/api/news`、`/api/announcements` | A负责新闻，B负责公告，互审 |
| `/news/:id` | 新闻标题、发布日期、富文本/安全正文 | `/api/news/{id}` | A / B |
| `/announcements/:id` | 公告详情与分类标记 | `/api/announcements/{id}` | B / A |
| `/projects` | 项目卡片列表、研发状态、进度条 | `/api/projects/progress` | B / A |
| `/projects/:id` | 项目详情、成员角色列表、空值回退 | `/api/projects/{id}` | B / A |
| `/competitions` | 创新竞赛与招募信息列表（上限20条） | `/api/platform/forum?limit=20` | A / B |
| `/competitions/:id` | 竞赛详情、招募人数、截止时间 | `/api/platform/forum/{id}` | A / B |
| `/resources` | 学习资料分类标签、分页加载、安全外链 | `/api/resources` | B / A |
| `/about` | 实验室介绍、研究方向、团队导师矩阵 | `/api/lab/info`、`/api/lab/team` | A / B |
| `/join` | 加入指南、官方投递邮箱、真实报名表下载 | 联系信息用 `/api/lab/info`；下载是静态文件 | A / B |
| `/search` | 全局搜索、按分类展现、精准详情跳转 | `/api/search` | B / A |
| `/growth` | 成长路线预留页（展示筹备说明，无虚构接口） | 首版不请求不存在的接口 | B搭骨架，A验证扩展 |
| `/:pathMatch(.*)*` | 404 兜底页及“返回首页”按钮 | 无 | B / A |

## 5. 开发代理与局域网真机联调核心机理

### 5.1 Vite 开发代理配置（解决跨域）
前端 API 请求统一使用相对路径 `/api/...`。由 B 同学在 `vite.config.js` 中配置 `server.proxy`：
```javascript
export default defineConfig({
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8081', // 测试后端真实地址
        changeOrigin: true
      },
      '/uploads': {
        target: 'http://localhost:8081',
        changeOrigin: true
      }
    }
  }
})
```
> [!WARNING]
> 绝对不要在前端代码里既写 `baseURL = '/api'`，又发起请求 `/api/news`，这会导致路径重复拼接成 `/api/api/news`。

### 5.2 局域网真机调试（电脑不是手机）
电脑浏览器的手机模拟器无法完全模拟真实的触控、输入法键盘弹起和屏幕裁切。必须真机验证：
```powershell
npm run dev -- --host 0.0.0.0
```
- 手机连接与电脑相同的局域网 Wi-Fi。
- 在手机浏览器中输入终端打印出的局域网地址（如 `http://192.168.x.x:5173`）。
- **常识警示**：手机里的 `localhost` 指向手机自身！这就是为什么代码中绝对不能把请求写死为 `http://localhost:8081`。手机发出相对路径 `/api` 后，由开发者电脑上的 Vite 代理转发到 Spring Boot 后端。

## 6. 必须亲自攻克的第一个真实网络闭环

目标只有一个：**打开移动端页面，从真实后端拉取新闻列表，完整验证“加载中、请求失败有重试、数据为空、正常渲染”四种状态，并能平滑进入新闻详情。**

### 6.1 核心请求封装 `src/api/http.js`
```javascript
export async function getData(path) {
  const response = await fetch(path)
  if (!response.ok) {
    throw new Error('网络请求异常：HTTP ' + response.status)
  }
  const result = await response.json()
  if (result.code !== 0) {
    throw new Error(result.message || '业务处理失败')
  }
  return result.data
}
```
- `response.ok`：拦截 HTTP 404/500 等协议层异常（fetch 不会自动把 404 当作 reject）。
- `result.code !== 0`：拦截 Spring Boot 统一返回体中的业务异常。
- 直接返回 `result.data`，业务页面无需在代码中反复嵌套 `.data`。

### 6.2 新闻业务接口 `src/api/news.js`
```javascript
import { getData } from './http.js'

export function getNewsList() {
  return getData('/api/news?limit=10')
}

export function getNewsDetail(id) {
  return getData(`/api/news/${id}`)
}
```

### 6.3 页面组件状态机范例 `src/views/NewsListView.vue`
```vue
<script setup>
import { ref, onMounted } from 'vue'
import { getNewsList } from '../api/news.js'

const items = ref([])
const loading = ref(false)
const error = ref('')

async function load() {
  loading.value = true
  error.value = ''
  try {
    items.value = await getNewsList()
  } catch (e) {
    error.value = e.message || '数据加载失败，请重试'
  } finally {
    loading.value = false
  }
}

onMounted(load)
</script>

<template>
  <div class="news-container">
    <h2>最新动态</h2>
    <div v-if="loading" class="tip-box">正在加载中...</div>
    <div v-else-if="error" class="tip-box error-box">
      <p>{{ error }}</p>
      <button type="button" @click="load">点击重试</button>
    </div>
    <div v-else-if="items.length === 0" class="tip-box">暂无相关动态</div>
    <ul v-else class="list-box">
      <li v-for="item in items" :key="item.id">
        <router-link :to="`/news/${item.id}`">
          <h3>{{ item.title }}</h3>
          <span>{{ item.publishDate || item.createTime }}</span>
        </router-link>
      </li>
    </ul>
  </div>
</template>
```
> [!TIP]
> 详情页需特别注意：同一个组件在连续切换不同 ID（如从 ID 1 切到 ID 2）时会被 Vue 复用。不能只在首次 `onMounted` 里加载，必须使用 `watch(() => route.params.id, ...)` 监听变化并重新请求。

## 14. 附录：给后端同学的前端实战避坑手册

| 常见现象 / 报错 | 顺着这里排查（第一反应） | 本质原因与技术点 | 解决招数 |
| :--- | :--- | :--- | :--- |
| **HTTP 状态码是 200，但页面却提示处理失败** | 看 Network 里返回的 JSON，找 `code` 和 `message` | HTTP 协议通信成功，不等于后端业务处理成功 | 后端返回了业务错误（如 `code: -1`），前端要解析并展示 `result.message` |
| **报错：Cannot read properties of undefined (reading 'map' 或 'length')** | 在 Network 中确认返回的 `data` 到底是个列表、带分页的对象还是 `null` | 数据结构没对齐，缺乏空值防御 | 变量初始化给 `ref([])`，在模板渲染前使用可选链或 `v-if` 做非空拦截 |
| **新闻列表传了 page 但页面死活不翻页** | 翻出接口文档核对新闻接口支持的 Query 参数 | 后端接口压根没做这个功能 | 新闻接口只支持 `limit`，后端没写分页逻辑就不要强行传 `page` |
| **点开公告详情，里面展示的居然是一篇新闻的内容** | 检查跳转的路由路径，以及组件内部调用的 API 函数名 | 数据隔离与命名疏忽 | 新闻和公告的数字 ID 极易撞车，检查是不是在公告页面错调了 `getNewsDetail` |
| **分类选“全部”时后端查不到任何数据** | 看看发出的网络请求是不是带了 `category=all` | 参数清洗不到位 | 选“全部”时传空字符串 `""` 或不传该参数，严禁把单词 `"all"` 当成类别发过去 |
| **电脑浏览器跑得欢，手机连上却一直在转圈或者报错** | 检查代码里的请求 URL 是否硬编码了 `localhost`，检查电脑防火墙 | 局域网网络拓扑常识 | 手机里的 `localhost` 指的是手机自己！必须在电脑启动 Vite 代理并访问电脑内网 IP |
| **首页头图或成员头像直接报 404** | 检查图片路径前缀是 `/uploads`、`/api/uploads` 还是本地路径 | 静态资源托管归属 | 后端上传图需配 Vite 代理转发到 `/uploads`，前端自备图标请放入 `public/` 目录 |
| **点进项目详情后 ID 变成了另一串数字或者直接 404** | 检查代码里是不是对 ID 执行了 `Number(id)` 或 `parseInt` | 大数值精度截断 | 雪花 ID 或长字符串主键在 JS 里转数字会丢精度，必须全程当作纯字符串处理 |
| **搜索框快速打字，最后屏幕上停在旧的搜索结果上** | 检查连续输入时是否有防抖，慢请求后返回把新请求冲掉了 | 异步网络请求竞态（Race Condition） | 加上请求防抖（Debounce），或者在发起新请求时记录序列号/取消先前请求 |
| **本地 `npm run dev` 正常，打包后白屏或静态资源全 404** | 检查 Vite 的 `base` 配置，以及路由是不是没有配置 Hash 模式 | 生产环境资源相对路径 | 首版严格使用 Hash 模式（`createWebHashHistory`），确保静态资源相对路径正确 |
| **GitHub PR 页面上的绿色 Merge 按钮是灰色的按不下去** | 检查是否有同伴的 Change requested 没撤销、CI 没跑过或代码有冲突 | 主分支保护机制在生效 | 解决冲突、拉最新代码、等待 CI 变绿、让同伴给出有效 Approve 即可解锁 |

本地已完成接口、页面、真实 MySQL、Ubuntu 容器转换、并发和重启验证。真实邮件投递按用户要求暂不验证；未连接生产服务器，不将本地通过等同于生产上线。

## 1 本机直接使用

当前前后端已在本机启动，仅监听本地地址：

| 用途 | 地址 |
| --- | --- |
| 在线填表 | http://127.0.0.1:5173/resume/apply |

| 简历后台 | http://127.0.0.1:5173/admin/resumes |
| 后端 | http://127.0.0.1:8081 |

本机使用 MySQL 8.0.40，开发库 `bdis`，限定库权限账号 `bdis_resume_dev`。开发管理员用户名为 `resume_dev`；随机密码、数据库凭据和 JWT 密钥保存在根目录 `.local/resume-dev.json`，已被 Git 忽略。请在本机打开该文件查看，不把内容复制到提交或公开文档。

当前库只为本功能初始化简历表、设置表和开发管理员，不代表其他旧模块的业务表或演示资料已导入。测试留下4条虚构报名记录，没有使用真实学生资料。默认邮件设置已恢复 AUTO、目标邮箱留空，本地启动脚本不提供真实 SMTP 发件凭据。

停止本任务启动的服务：

```powershell
Set-Location D:\java\BDIS-Official-Website
& .\scripts\stop-resume-dev.ps1
```

重新构建并启动：

```powershell
& .\scripts\start-resume-dev.ps1
```

仅在已经构建且后端源码没变化时可加 `-SkipBuild`。停止脚本核对本次记录的进程 ID 和创建时间；启动脚本遇到8081/5173占用会退出，不关闭其他程序。日志在 `.local/backend.log`、`backend-error.log`、`frontend.log`、`frontend-error.log`。MySQL 服务、Docker 引擎由本机管理，脚本不会替用户停止它们。

本机已有 Java17、Maven3.9.9、Node22.23.2、npm依赖及Docker引擎。首次在其他机器准备时：安装 Java17、Maven、Node22（至少22.13）、MySQL及Docker；在 `bdis-web` 执行 `npm ci`。本地启动脚本读取上述私有 JSON，只适用于已准备开发配置的 Windows 环境；生产不使用该脚本或开发凭据。

## 2 操作流程

1. 填写独立表单并生成预览，成功后进入独立预览页。浏览器绘制全部 PDF 页面后才能确认。
2. 可下载当前 Word 后本地贴照，或上传照片在线合成；换照成功后以新版本为准。照片建议600×900、2:3，JPEG/PNG，单张≤5MB，明显不符比例会拒绝。
3. 本地改过 Word 时必须重新上传并预览；上传文件按原件保存，不使用旧预览代替它。手工 Word 最多10MB，只支持有效 DOCX。
4. 实际 PDF 必须一到两页，超限或转换失败不会形成可确认版本。页面保留输入并提供模板下载/手工上传入口，不截断正文。
5. 确认后保存 Word、PDF、表单快照索引；后台可查询、预览、下载，切换模式和目标邮箱。邮件失败不撤销保存。

按北京时间每年9月1日切换学年；学号按字符串保留前导零。文件名示例：`张三-00001234-2026学年-2027学年大数据智能工作室招新报名表.docx`。换照和正式保存沿用该预览生成时的学年。

## 3 转换镜像与 Ubuntu 运行

仓库提供 `deploy/resume-converter.Dockerfile`，基于 Ubuntu24.04，安装 LibreOffice Writer、Noto CJK 和 fontconfig。本地实测 LibreOffice24.2.7。构建上下文只使用 deploy 目录：

```bash
docker build -f deploy/resume-converter.Dockerfile -t bdis-docx-tools:ubuntu24.04 deploy
```

后端会为每次转换创建临时容器，不需要常驻转换服务。容器禁用网络、限制1CPU/768MB/256进程，转换串行执行，最多2个等待任务；第四个生成请求返回429。转换30秒、整个生成请求120秒超时，独立用户配置目录，结束清理本次容器。不要把其他业务的容器交给本功能清理。

Ubuntu 上可选择原生转换以减少容器启动成本：

```bash
sudo apt-get update
sudo apt-get install --no-install-recommends libreoffice-writer fonts-noto-cjk fontconfig
fc-cache -f
soffice --version
```

配置 `BDIS_RESUME_CONVERTER=native`、`BDIS_LIBREOFFICE_PATH=/usr/bin/soffice`。原生模式没有Docker的768MB硬限制，应在服务管理器设置整体内存/CPU上限，重新检查实际转换效果。当前实际转换验证使用本机Docker的Ubuntu环境；生产宿主系统、CPU架构、原生模式和Linux文件属主适配仍需在目标机器复验。

若使用 Docker 模式，后端运行用户需能调用 Docker 引擎；私有文件根目录必须是宿主机真实路径，镜像需在同一引擎内。当前方案后端作为宿主机 Java 进程运行，未设计“后端再套容器且任意路径挂载”的编排。

## 4 后端、数据库与备份

先检查目标库是否已有 `resume_submission`：

| 情况 | 使用的脚本 |
| --- | --- |
| 无简历表 | `bdis-website/sql/resume_submission_migration.sql`，建立完整简历表和设置表 |
| 已有旧简历表 | 备份并核对结构后使用 `bdis-website/sql/resume_submission_upgrade.sql`，补字段/索引/设置表，不清空原数据 |

upgrade 使用临时存储过程，需要执行DDL及创建/删除过程权限；使用迁移管理员执行，不给日常运行账号额外服务器级权限。已在独立临时MySQL库对旧结构连续执行两次验证，原记录保留；目标线上结构尚未知，不能跳过备份和结构核对。原有业务表仍按项目原部署方式准备。

生产数据库用户只授予所需业务库权限；DDL完成后，运行期主要需要SELECT/INSERT/UPDATE。不要使用本地root密码或开发JWT密钥部署。后端必要环境变量：

| 变量 | 含义 |
| --- | --- |
| `BDIS_DB_URL` | 目标MySQL JDBC地址，指定业务库、UTF-8和Asia/Shanghai |
| `BDIS_DB_USERNAME` / `BDIS_DB_PASSWORD` | 专用运行账号及密码 |
| `BDIS_JWT_SECRET` | 独立高强度密钥 |
| `BDIS_RESUME_STORAGE_ROOT` | 私有文件绝对路径，例如 `/var/lib/bdis/private-resumes` |
| `BDIS_RESUME_CONVERTER` | `docker` 或 `native`，配置默认native，本机脚本使用docker |
| `BDIS_RESUME_DOCKER_IMAGE` | Docker模式镜像，默认 `bdis-docx-tools:ubuntu24.04` |
| `BDIS_DOCKER_PATH` / `BDIS_LIBREOFFICE_PATH` | 对应程序路径，默认docker/soffice |

构建：

```bash
mvn -f bdis-website/pom.xml clean package -DskipTests
java -Xms128m -Xmx512m -jar bdis-website/target/bdis-website-0.0.1-SNAPSHOT.jar
```

用 systemd 或现有服务管理方式保存环境、重启策略和日志。示例命令省略敏感环境值，不能直接作为生产账号配置。私有目录必须在 uploads、前端public、Nginx网站根目录之外，运行账号可读写；禁止通过静态映射或软链接公开。

MySQL保存记录及设置，文件系统保存正式 Word/PDF，恢复必须同时备份两者。正式文件不随预览清理删除；临时凭证30分钟有效，每10分钟清理过期预览，异常遗留工作目录超过2小时清理。旧版本曾保存在公开uploads的附件不自动搬迁，需要单独核对访问范围。

4核4GB目标服务器尚未实测。本地后端测试JVM堆上限512MB，实际进程峰值工作集约394MB；转换容器上限768MB。需为MySQL、系统和其他业务保留内存，不能把该上限当作整机峰值测量结果。

## 5 前端与 Nginx

在 `bdis-web` 执行 `npm ci` 和 `npm run build`，部署dist到现有站点。生产前端是静态文件，不需要常驻Vite或Node进程。PDF.js worker为`.mjs`，必须按JavaScript MIME返回，不能落入HTML页面回退。

按实际站点合并如下配置；已有HTTPS、站点根目录等保持实际部署配置：

```nginx
client_max_body_size 12m;

location /api/ {
    proxy_pass http://127.0.0.1:8081;
    proxy_read_timeout 150s;
}

location ~ \.mjs$ {
    types { application/javascript mjs; }
    try_files $uri =404;
}

location / {
    try_files $uri $uri/ /index.html;
}
```

API文件响应禁止缓存；不要为简历接口额外添加公开缓存规则或把私有目录映射为网站目录。生产复验直接打开/刷新三条resume路由、管理员登录鉴权、worker MIME、中文字体、两页分页、照片及文件名。

## 6 邮件后续配置

业务设置保存在 `resume_settings`，后台可以更换目标邮箱和AUTO/MANUAL。发件端需要邮箱服务提供的SMTP账号和授权码；通常不是在网页邮箱里登录一次即可。当前账号及授权码均为空，所以本地不会真实发送。

未来启用时通过环境提供 `BDIS_MAIL_HOST`、`BDIS_MAIL_PORT`、`BDIS_MAIL_USERNAME`、`BDIS_MAIL_PASSWORD`。当前配置按465端口SSL及SMTP认证编写；默认主机smtp.163.com。若目标服务仅支持587/STARTTLS，须先按该服务要求调整邮件配置，不能只改端口。

先在MANUAL模式、虚构报名和指定测试收件邮箱上验证，再根据需要切回AUTO。状态2表示SMTP接受，不保证到达收件箱；状态3或重启后的结果不确定应先核实再补发。修改模式或目标地址不会自动发送历史记录。
